● 我来解释一下 NotifyTimeRange 和 NotifyChannelEvent 这两个独立数据库表的作用：

  1. NotifyTimeRange 表的作用

  表结构：
  CREATE TABLE IF NOT EXISTS notify_channel_time_ranges (
      id SERIAL PRIMARY KEY,
      channel_id VARCHAR(36) NOT NULL REFERENCES notify_channels(id) ON DELETE CASCADE,
      start_time TIME NOT NULL,
      end_time TIME NOT NULL,
      weekdays JSON NOT NULL DEFAULT '[]',
      created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
      UNIQUE(channel_id, start_time, end_time, weekdays)
  );

  作用：
  - 灵活的时间段管理：每个通知渠道可以设置多个不同的通知时间段
  - 精细化控制：支持按星期几和具体时间范围来控制通知发送
  - 避免打扰：可以设置工作时间、休息时间等不同的通知策略

  使用场景示例：
  // 一个渠道可以有多个时间段配置
  [
    {
      "start_time": "09:00",
      "end_time": "12:00",
      "weekdays": [1, 2, 3, 4, 5]  // 工作日上午
    },
    {
      "start_time": "14:00",
      "end_time": "18:00",
      "weekdays": [1, 2, 3, 4, 5]  // 工作日下午
    },
    {
      "start_time": "10:00",
      "end_time": "16:00",
      "weekdays": [0, 6]  // 周末时间
    }
  ]

  2. NotifyChannelEvent 表的作用

  表结构：
  CREATE TABLE IF NOT EXISTS notify_channel_events (
      id SERIAL PRIMARY KEY,
      channel_id VARCHAR(36) NOT NULL REFERENCES notify_channels(id) ON DELETE CASCADE,
      event_type VARCHAR(50) NOT NULL,
      min_severity VARCHAR(20) DEFAULT 'low',
      created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
      UNIQUE(channel_id, event_type)
  );

  作用：
  - 事件订阅管理：每个渠道可以订阅特定的事件类型
  - 严重级别过滤：可以为每个事件类型设置最低严重级别
  - 灵活配置：不同渠道可以订阅不同的事件组合

  使用场景示例：
  // 飞书渠道：订阅所有重要事件
  [
    {
      "event_type": "email_sync_failed",
      "min_severity": "high"  // 只接收高严重级别的同步失败
    },
    {
      "event_type": "system_error",
      "min_severity": "medium"  // 中等及以上的系统错误
    }
  ]

  // 邮件渠道：只订阅关键事件
  [
    {
      "event_type": "system_error",
      "min_severity": "critical"  // 只接收严重的系统错误
    },
    {
      "event_type": "database_error",
      "min_severity": "high"
    }
  ]

  为什么使用独立表而不是 JSON 字段？

  1. 查询性能：
    - 可以高效地查询哪些渠道订阅了特定事件
    - 可以快速判断当前时间是否在允许的通知时间段内
  2. 数据完整性：
    - 使用外键约束确保数据一致性
    - 可以使用唯一索引防止重复配置
  3. 灵活扩展：
    - 未来可以为时间段或事件订阅添加更多属性
    - 便于统计分析（如哪些事件被订阅最多）
  4. 管理便利：
    - 可以独立管理时间段和事件订阅
    - 支持批量操作（如一次更新所有渠道的某个事件订阅）

  这种设计让通知系统具有很高的灵活性，可以实现精细化的通知管理策略。
